# Zig low-level feed server

This submission is a standalone Zig 0.13.0 server. It uses one level-triggered Linux `epoll` loop for both listeners and keeps idle HTTP/1.1 sockets as small connection records; request and response buffers are allocated only while a request is active. A bounded 16-worker pool (override with `DB_POOL`, maximum 512) gives each worker one libpq connection, so blocking PostgreSQL round trips never block the socket loop. Each worker has its own request and completion queue, and the connection record is the queue node, avoiding a heap allocation for every handoff. The default pool reserves one write lane, leaving the rest for the read-heavy challenge workload; `WRITE_WORKERS` can tune the split. Write lanes group up to 64 queued writes in one transaction and release responses only after commit; a failed group is rolled back and retried one request at a time. Workers prepare the four fixed SQL statements once per connection and execute those prepared statements thereafter. The hot feed response is cached per process for one second and invalidated when a post is created, avoiding a database round trip during read bursts. Responses are gzip-compressed when the client advertises it, using Zig's fast native compressor. The workers issue the SQL from `SPEC.md` and format JSON in the process. JWT HS256 checks use OpenSSL HMAC, and the JSON/HTTP parsers are allocation-light.

`install.sh` installs the pinned official Zig 0.13.0 archive and, on Ubuntu, the `libpq-dev` and `libssl-dev` headers used by `@cImport`. `build.sh` links `libpq` and `libcrypto` and emits `feed-zig`; `start.sh` runs it in the foreground. Set the `DATABASE_URL`, `JWT_SECRET`, `HOST`, `PORT`, and optional `EXTRA_PORT` variables from `SPEC.md` before starting.
